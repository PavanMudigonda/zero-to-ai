# Zero to AI — Docusaurus Migration Demo

This folder is a **proof-of-concept migration** of the Zero to AI curriculum from
the existing **Nextra / Next.js** site (`../next-docs`) to **Docusaurus 3**.

It is intentionally self-contained: it lives alongside the current site and does
not modify or replace it. The goal is to demonstrate *how* a migration would work
and what the trade-offs are.

---

## TL;DR

```bash
cd docusaurus-site
npm install
npm run migrate     # generate docs/ from ../next-docs notebooks (subset)
npm start           # dev server at http://localhost:3000
npm run build       # static production build
```

Migrate everything instead of the demo subset:

```bash
npm run migrate -- --all
```

## What was migrated, and how

| Concern | Nextra (current) | Docusaurus (this demo) |
| --- | --- | --- |
| Site framework | Next.js App Router + `nextra-theme-docs` | Docusaurus 3 classic preset |
| Content source | Jupyter notebooks rendered by a custom `<DynamicNotebook>` | Notebooks converted to Markdown at build-time by `scripts/migrate-from-nextra.mjs` |
| Sidebar order/titles | `next-docs/src/app/_meta.ts` | `_category_.json` + `sidebar_position` front matter (autogenerated sidebar) |
| Math (LaTeX) | `nextra({ latex: true })` | `remark-math` + `rehype-katex` |
| Diagrams (Mermaid) | custom `ZoomableMermaid` component | `@docusaurus/theme-mermaid` |
| Code copy button | `defaultShowCopyCode` | built-in |
| Routing | files under `src/app/**` | `docs/**` with `routeBasePath: '/'` |
| Output | `next build` static export | `docusaurus build` static output |

### The migration script

[`scripts/migrate-from-nextra.mjs`](scripts/migrate-from-nextra.mjs) is the heart
of the demo. It:

1. Parses the top-level [`_meta.ts`](../next-docs/src/app/_meta.ts) to recover the
   chapter order and titles.
2. Reads each chapter's primary Jupyter notebook (the file the Nextra site fed to
   `<DynamicNotebook>`) and converts it to Markdown:
   - markdown cells &rarr; raw markdown
   - code cells &rarr; <code>```python</code> fenced blocks
   - LaTeX `$...$` and <code>```mermaid</code> blocks are preserved
3. Emits Docusaurus front matter (`title`, `sidebar_position`, `format: md`) and a
   per-chapter `_category_.json` so the **autogenerated** sidebar reproduces the
   exact ordering from `_meta.ts`.
4. Recurses into chapter-level `_meta.ts` files (e.g. `00-course-setup`) to migrate
   sub-pages.

> `format: md` forces CommonMark parsing so raw notebook prose (which can contain
> `{`, `}` or `<...>`) does not break the MDX compiler.

By default it migrates a **representative subset** of chapters
(`00-course-setup`, `01-python`, `02-data-science`, `08-rag`, `15-ai-agents`) so
the demo stays reviewable. Use `--all` for the full curriculum.

## What is intentionally **not** solved here

This is a demo, not a finished migration. Known gaps:

- **Interactive notebooks.** The Nextra site executes Python in-browser via
  `@jupyter-kit` / Pyodide. This demo renders notebooks as *static* Markdown
  (code + prose). Reproducing live execution in Docusaurus would need a custom
  React component or an embed (e.g. JupyterLite).
- **Custom React widgets.** `CurriculumHome`, `ProgressWidget`, and `FuzzySearch`
  are bespoke Nextra components. Docusaurus equivalents (or a swizzle) would be
  needed; the homepage here is a generated index instead.
- **Cell outputs.** Notebook *outputs* (plots, tables) are not embedded; only
  source is converted. nbconvert-style output capture could be added.
- **Redirects.** URL parity is close (`routeBasePath: '/'`) but any changed paths
  would need `@docusaurus/plugin-client-redirects`.

## Why consider Docusaurus

- First-class versioning, i18n, and search (Algolia / local) out of the box.
- Large plugin/theme ecosystem and a stable, docs-focused data model.
- MDX + React for interactive content where needed.

## Why staying on Nextra may still be right

- The current site already renders **live, executable** notebooks — the single
  most valuable feature here and the hardest to port.
- Significant custom tooling (sidebar synthesis, search, progress tracking) is
  already built and working.

The recommendation captured by this demo: **migration is feasible and the
content/IA ports cleanly**, but the in-browser notebook execution is the decisive
factor and would require dedicated work before a full switch.
